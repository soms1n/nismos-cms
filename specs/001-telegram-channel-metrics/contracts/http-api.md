# HTTP-контракт: метрики Telegram-канала

Базовый путь: `/api`. Все ответы метрик имеют `Cache-Control: no-store`. Дата и время передаются в UTC в формате ISO 8601. Браузер никогда не получает Telegram session string, идентификаторы участников или данные отдельных подписчиков.

## Авторизация

- Оба endpoint требуют активной административной сессии.
- `401 Unauthorized`: сессия отсутствует или недействительна.
- `403 Forbidden`: идентичность не входит в серверный allowlist администраторов.
- Проверка выполняется внутри каждого обработчика, а не только на странице или в middleware.

## GET /api/metrics

Возвращает последний успешный снимок без нового обращения к Telegram.

### Ответ 200

```json
{
  "metrics": {
    "total": 1000,
    "deleted": 120,
    "real": 880,
    "startedAt": "2026-11-10T12:00:00.000Z",
    "updatedAt": "2026-11-10T12:00:02.000Z"
  },
  "state": "current"
}
```

- `state=current`: последний обход завершился успешно.
- `state=stale`: последний обход завершился ошибкой; возвращённые значения являются прежним снимком и должны быть явно обозначены устаревшими.
- Всегда выполняется `total = deleted + real`.

### Ответ 503

Возвращается, если ещё нет ни одного успешного снимка.

```json
{
  "error": {
    "code": "METRICS_UNAVAILABLE",
    "message": "Метрики ещё не получены. Запросите обновление."
  }
}
```

## POST /api/metrics/refresh

Запускает новый полный обход или присоединяется к уже выполняющемуся. Тело запроса отсутствует. Разрешаются только запросы того же origin; проверяются `Origin` и/или `Sec-Fetch-Site`.

### Ответ 200

Новый полный снимок в формате `GET /api/metrics` со `state=current`. Все три значения и timestamps относятся к одному завершённому обходу.

### Ошибки

```json
{
  "error": {
    "code": "TELEGRAM_SOURCE_UNAVAILABLE",
    "message": "Не удалось получить актуальные метрики. Попробуйте позже."
  }
}
```

| HTTP | Код | Условие |
|------|-----|---------|
| `401` | `UNAUTHENTICATED` | Нет действительной сессии |
| `403` | `FORBIDDEN` | Нет прав администратора |
| `429` | `REFRESH_RATE_LIMITED` | Слишком частые обновления; ответ содержит `Retry-After` |
| `502` | `TELEGRAM_ACCESS_DENIED` | Канал недоступен или список участников скрыт |
| `502` | `TELEGRAM_SOURCE_UNAVAILABLE` | Ошибка Telegram, обрыв обхода или `FLOOD_WAIT` без допустимого ожидания |
| `502` | `SNAPSHOT_INCOMPLETE` | Дубли/пропуски, противоречивые счётчики или неполный обход |
| `502` | `CLASSIFICATION_INCOMPLETE` | Есть участники без надёжной классификации |
| `504` | `REFRESH_TIMEOUT` | Превышен предельный таймаут обновления |

При ошибке частичные значения не возвращаются как новый снимок. Клиент сохраняет прежние значения только в состоянии `stale`; при их отсутствии показывает состояние недоступности.

## Согласованность и нагрузка

- Повторные нажатия во время обновления не создают параллельные обходы.
- Кнопка обновления недоступна на клиенте до завершения запроса, но серверная защита обязательна независимо от клиента.
- Таймаут и ограничение частоты защищают Telegram-сессию и панель от лишних запросов.
- Авторизационные маршруты Auth.js не входят в этот контракт.
