# Модель данных: метрики аудитории Telegram-канала

## TelegramChannel

Представляет один заранее настроенный канал.

| Поле | Тип | Правила |
|------|-----|---------|
| `channelRef` | строка | Серверная конфигурация; не передаётся браузером |
| `title` | строка, необязательно | Название для отображения после успешного подключения |

**Связи**: один канал имеет не более одного последнего успешного `AudienceSnapshot` в памяти процесса.

## AudienceSnapshot

Агрегированный результат одного полного обхода участников. Хранится только последний успешный экземпляр.

| Поле | Тип | Правила |
|------|-----|---------|
| `total` | целое число | `>= 0`; число уникальных классифицированных участников |
| `deleted` | целое число | `>= 0`; число участников с `deleted=true` |
| `real` | целое число | `total - deleted` |
| `startedAt` | UTC date-time | Начало обхода |
| `updatedAt` | UTC date-time | Успешное завершение обхода; `updatedAt >= startedAt` |

**Инварианты**:

- `total = deleted + real` для каждого опубликованного снимка.
- Все значения получены из одного обхода; независимый общий счётчик Telegram не подставляется в `total`.
- Снимок публикуется только после полного обхода и успешной классификации всех собранных участников.
- Новый снимок атомарно заменяет предыдущий; частичный результат не перезаписывает последний успешный.
- Снимок не утверждает атомарность Telegram на один момент: интервал сбора ограничен `startedAt` и `updatedAt`.

## ParticipantClassification

Временная запись, существующая только во время обхода. Не сохраняется после вычисления агрегатов.

| Поле | Тип | Правила |
|------|-----|---------|
| `participantId` | строка | Используется только для дедупликации в памяти обхода |
| `classification` | `deleted` \| `real` \| `unknown` | `real` только при полном объекте пользователя без `deleted=true` |

**Правила классификации**:

- `deleted=true` → `deleted`.
- Полный объект пользователя без признака `deleted` → `real`.
- `userEmpty`, отсутствующий объект пользователя, неполные данные или неподдерживаемый тип участника → `unknown`.
- Любой `unknown` делает весь новый снимок непригодным для публикации.
- Признаки `bot`, `fake` и `scam` не меняют классификацию `real`, поскольку выявление ботов не входит в объём.

## AdminIdentity

Идентичность администратора, полученная от внешнего провайдера.

| Поле | Тип | Правила |
|------|-----|---------|
| `issuer` | строка | Идентификатор провайдера |
| `subject` | строка | Стабильный идентификатор пользователя у провайдера |

**Правила**: доступ разрешён только если пара `issuer + subject` присутствует в серверном allowlist. Email сам по себе не является критерием доступа. Пара проверяется при каждом запросе метрик.

## Состояния панели

```text
empty ──start refresh──> refreshing
refreshing ──success──> current
refreshing ──failure, no previous snapshot──> unavailable
refreshing ──failure, previous snapshot exists──> stale
current|stale|unavailable ──start refresh──> refreshing
```

- `current`: показан последний успешный снимок и `updatedAt`.
- `stale`: прежний снимок можно показать только с явной пометкой, что обновление не удалось; он не называется текущим.
- `unavailable`: метрик нет; показано понятное сообщение и доступно повторное обновление.
- Параллельные запросы обновления объединяются в один обход, чтобы не создавать конкурирующие снимки.

## Хранение и приватность

- В постоянном хранилище отсутствуют метрики и персональные данные подписчиков.
- После перезапуска процесса состояние начинается с `empty` и требует нового обхода.
- Браузер получает только агрегаты и timestamp; ID, имена, признаки отдельных пользователей и Telegram session string не входят в ответ.
